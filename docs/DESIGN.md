# ReconDesk design decisions

User direction, retained from the conversation: "Terang, rapi seperti aplikasi kerja." The user authorized the ReconDesk transaction-comparison proposal. The following implementation decisions interpret that direction; they are not additional user quotations.

Reading this as an operational workspace for investigators and reviewers, in a light paper-and-ledger visual language, ENERGY 1 / RHYTHM 2 / MOTION 1.

- Light neutral surfaces support reading dense source records during work. A restrained ink/green accent identifies the current action; exceptional states use labels as well as color.
- A run list leads into an exception ledger and then a two-source comparison. This follows the actual investigation task rather than a generic marketing layout.
- System sans-serif text avoids another font download. Monospaced text is restricted to references and aligned monetary values, where matching characters matters.
- Compact row spacing keeps related records together; larger section gaps separate source evidence, proposed explanation, and review decisions.
- Flat surfaces and small input/button radii distinguish working areas from overlays. Shadows, if used, indicate a real overlay only.
- The repeated identity motif is paired source evidence: internal and partner records are compared with the same labels and columns throughout the application.
- State labels describe actual stored workflow status. Counts are calculated by the API, not invented for a dashboard.
- Motion is limited to focus, hover and short state transitions. No autoplay, entrance choreography, gradients, decorative status dots, or stock illustration is needed to reconcile transactions.
- The mobile interface reflows navigation and comparisons; genuinely tabular evidence has a labeled local scroll region. Controls have accessible names and usable touch targets.

Root performs the final visual and functional gate after the implemented app is running. See UX-REVIEW.md for the resulting evidence, not this design intent.
